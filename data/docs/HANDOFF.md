> **실제 구축 시작점**：[도서관별 데이터셋 작업 지시서](DATASET_BUILD_TASKS.md)를 먼저 읽고 [27관 작업표](../catalog/library_build_tasks.csv)에서 작업ID를 배정한다. 아래 문서는 조사 근거·도서관별 추출 방법이며, 새 지시서가 납품 파일·형식·완료 기준을 보완한다.

## 1. 목표와 현재 상태

목표는 공공도서관의 실제 좌석을 지도 위에 표시하고, 화장실·출입구·냉방·조명·콘센트·책상·창문 등의 특성으로 개인화 추천에 활용할 수 있는 정적 데이터셋을 구축하는 것이다. 학교도서관은 제외한다. 추천 후 선택·이용 확인은 별도 행동 DB로 수집한다.

**현재 완성본이 아니다.** 2026-11-14에 세 에이전트가 공공 API, 실제 공개 CSV, 배치도·좌표화 방법을 나눠 조사했다. 초기 24관(용인 11관 + 성남 13관)과 도면을 직접 확인한 추가 3관을 `catalog/library_feasibility.csv/json`에 각각 1행으로 정리했다. 전국 전체 도서관을 완전 조사한 목록은 아니다. 기존 `Data/`의 163건 카탈로그도 검색에 참고했다.

- 사용자 제공 성남중앙 캡처: **169개 좌석 사각형 검출 및 RapidOCR 실행 완료**. 고유 번호 169개. 시설 좌표 없음.
- 용인 공식 웹: **1,318개 정적 좌석 사각형 추출**. 공식 번호·ID와 전수 매핑 미완료. 시설 좌표 없음.
- 국립중앙·해운대·계양: 원본 도면을 실제 열어 시각 검토했다. 좌석·시설의 자동 추출은 아직 실행하지 않았다.
- 전체 좌석·전체 시설을 검증까지 마친 도서관은 0관이다.

- 성남 `https://www.snlib.go.kr/robots.txt`: `User-agent:*`, `Disallow:/`. 직접 수집을 중단했다. 사용자 캡처를 처리한 것은 사이트 수집을 우회한 것이 아니다. 나머지 성남 도서관의 자료도 제공받은 파일이나 별도로 허용된 배포본으로 확보한다.
- 용인 `https://lib.yongin.go.kr/robots.txt`: 일반 UA의 조사 경로 금지가 확인되지 않았다. **공식 내비게이션에 실제 링크된 경로만** 사용했다.
- 국립중앙 `https://www.nl.go.kr/robots.txt`: `Allow:/` 확인.
- 수집 전 정책을 다시 확인한다. 목적을 User-Agent로 밝히고 요청 사이 최소 1초, 실패 시 재시도 최대 2회. 인증·접근 제한·시간 초과 시 다른 숨은 API를 추측해 탐색하지 않는다.
- 원본 현황 HTML·화면의 색·사용 상태·성별·개인 이용 시각은 저장하지 않는다. 좌석 위치 추출은 허용 목록 필드만 저장한다.

## 4. 성남중앙: 사용자 캡처로 실제 좌표화한 결과

원본은 `/home/stadium/.univdash/uploads/76e3778271ac-pasted-20261114075747.png`, 4054×2368픽셀이다. 저장소에 원본을 복사하지 않았다. 원본 SHA-256은 `validation/seongnam_central_A.json`에 있다.

**실행한 방법:** OpenCV 포화도 기반 연결 영역에서 좌석 사각형만 검출 → 버튼 내부 어두운 글자만 OCR 입력 → RapidOCR로 좌석번호 인식 → CSV/JSON/SVG 생성. 색은 검출에만 사용하고 색·사용 상태·성별은 저장하지 않았다. 한국어 OCR이 아니라 `A숫자` 번호 인식이다.

신뢰도는 정확도가 아니다. 169개 전수 육안 검수는 완료하지 않았다. **현재 SVG는 실제 건축 평면도가 아니라 좌석 버튼의 화면 배치 재구성**이다. 시설 위치를 상대 화면 좌표만으로 끼워 넣지 않는다.

좌표는 두 종류다.

- `캡처X/Y`: 전체 4054×2368 이미지의 좌상단 기준.
- `X/Y좌표`: 표시 영역 `(x=48,y=582,width=3772,height=1786)`의 좌상단 기준. `X=캡처X-48`, `Y=캡처Y-582`.
- `정규화X/Y`: 위 표시 영역의 가로·세로로 나눈 값. 가로·세로 정규화도 저장했다.
- 예: A93은 캡처 (2160, 699), 지도 (2112, 117), 크기 66×56이다.
- 화면 배율이나 캡처 크기가 달라지면 같은 원시 좌표를 재사용하지 않는다. 해당 원본별 지도 프레임을 새로 정의한다.

**과거 정원과 충돌:** 성남 공개 CSV는 A구역 106석·중앙 전체 608석이지만 사용자 캡처는 A구역 169석·전체 671석이다. 과거 CSV 숫자로 현재 좌석을 잘라내면 안 된다. 169개 좌석 추출은 캡처의 A구역만 대조한 결과이며, B구역 70석·4층 216+216석은 아직 구조화하지 않았다.

다음 작업:

1. 위 8개와 전체 169개 번호를 원본과 대조하고 검수 상태를 갱신한다.
2. B구역과 4층의 두 열람실은 **사용자 제공 또는 허용된 원본**을 확보한다.
3. 공식 좌석 ID와 표시번호는 별개다. 현재 `공식좌석ID`는 null이며 내부 객체 ID와 표시번호만 있다.
4. 화장실·출입구·설비가 그려진 현재 층별 평면도를 확보한다.
5. 벽 모서리·출입문 등 공통 기준점이 없는 버튼 화면은 건축 평면도와 자동 정합했다고 판정하지 않는다. 방 연결 관계를 먼저 만들고 좌석 실측을 보완한다.

### HTML 추출과 번호 매핑

- 동백 등의 `div`에 `position:absolute;left;top;width;height`가 있다. 흥덕은 `TABLE`이다. 태그를 div로만 제한하면 흥덕을 놓친다.
- 사용 중 좌석의 숫자가 `사용`으로 대체돼 전체 번호가 원문에서 보이지 않는다. 조사한 요소에는 이를 복원할 별도 ID·onclick·data 속성이 확인되지 않았다.
- DOM 순서, 빈 번호, 배열 패턴으로 숨겨진 번호를 추정하지 않는다. 여러 시간대 현황을 모아 번호를 복원하는 작업도 이번 정적 수집 범위에 넣지 않는다.
- 전체 번호가 표시되는 사용자 캡처 또는 공식 정적 번호도를 확보한 뒤 `도서관+방+표시번호`와 공공 CSV의 좌석 ID를 대응시킨다.
- 기하 객체 ID와 공식 좌석 ID 사이에 별도 매핑 테이블을 만들고 미확인은 null로 남긴다.

### 좌표 프레임

흥덕 배경 원본은 1500×1050, HTML 표시 크기는 1000×700이다. 원본 이미지 좌표로 옮기려면 X/Y/폭/높이를 1.5배 한다. 또는 웹에서 1000×700 프레임을 유지한다. 다른 관·다른 탭에 이 배율을 복사하지 않는다. 각 페이지의 실제 렌더 크기·테두리·패딩·transform을 따로 확인해야 한다.

층별도와 방 단독 배경은 별도 지도다. 공통 기준점이 최소 3개 있으면 아핀 변환(affine transform)을 구하고, 원근 변환이 필요하면 4개 이상으로 호모그래피(homography)를 구해 검수한다. 실제로 공통 기준점을 찾을 수 없으면 변환을 만들어내지 말고 **층별 통로 그래프 + 방 진입 노드**로 연결한다. 좌석 버튼 화면은 책상·의자의 실제 외곽을 보장하지 않는다.

## 8. 전체 좌석·시설 구조화 파이프라인

1. **원본 등록:** 도서관·건물·층·방, URL, 원본 날짜, 수집일, 해시, 이미지 해상도, 이용조건, 도면 범례를 저장한다.
2. **좌표 프레임 정의:** 층 전체도·방 도면·캡처·사진마다 별도의 `map_id`를 부여한다. 원점은 좌상단이며 X축은 오른쪽, Y축은 아래쪽이다. 픽셀(pixel)과 미터(meter)를 분리한다.
3. **기존 좌표 우선 사용:** HTML/CSS/SVG에 좌표가 있으면 파싱한다. 좌석 버튼의 외곽과 실제 책상의 외곽은 구분한다.
4. **벡터 PDF 처리:** [PyMuPDF get_drawings](https://pymupdf.readthedocs.io/en/latest/recipes-drawing-and-graphics.html)로 경로·사각형·선을 읽고, [get_text](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)로 단어의 경계 상자(bbox)를 읽는다. 장식·책장과 좌석을 구분하는 의미 검수가 필요하다.
5. **래스터 처리:** [PaddleOCR](https://www.paddleocr.ai/latest/en/version3.x/module_usage/text_detection.html) 또는 실행을 검증한 [RapidOCR](https://github.com/RapidAI/RapidOCR)로 번호·명칭의 경계 상자를 추출한다. 객체 검출이나 반복 도형 검출 결과를 좌석번호와 결합한다.
6. **아이콘·구획 추출:** [SAM2](https://github.com/facebookresearch/sam2)는 마스크 후보를 만드는 보조 도구다. 좌석·에어컨을 자동으로 정확히 분류하는 전용 모델은 아니다. 의미 분류, 범례 확인, 사람의 검수가 필요하다.
7. **ID 대응:** 표시번호와 공식 좌석 ID의 매핑을 별도로 검증한다. 번호가 없는 좌석에는 내부 ID를 부여하고 외부 ID는 `null`로 둔다. 번호의 공백을 임의로 채우지 않는다.
8. **시설 라벨링:** 화장실은 영역과 출입구 접근점을 함께 저장한다. 창문은 선 또는 면으로, 에어컨·등·콘센트는 설비 위치로 구조화한다.
9. **지도 정합:** 방 도면과 층별도 사이의 변환은 근거가 있는 기준점으로 추정하고, 중첩하여 검수한다. 정합할 수 없으면 방 입구 노드를 통해 지도 사이의 관계만 연결한다.
10. **경로 구성:** 좌석 → 방 출입문 → 복도 → 화장실 문을 연결한 그래프에서 최단 경로를 구한다. 축척을 모르면 픽셀 또는 상대 거리만 표시하며, 미터 단위 거리를 임의로 만들지 않는다.
11. **환경 특성 보완:** 설비의 위치를 아는 것과 실제 쾌적성을 아는 것은 다르다. 아래 표의 보완 자료를 확보한다.
12. **검수 통과 자료만 서비스에 게시:** 후보 파일을 그대로 추천 엔진에 전달하지 않는다.

| 특성 | 기존 자료·AI로 할 수 있는 작업 | 추가로 확보할 자료 |
|---|---|---|
| 화장실 | 도면의 아이콘·구역·문 추출 | 층과 출입 가능 여부, 복도 연결, 축척 |
| 에어컨 | 설비 기호가 명시된 경우 기기 위치 추출 | 기계/HVAC 도면 또는 현장 위치. 바람 방향·강도·작동 조건은 별도 측정 |
| 조명 | 등기구·창문 기호의 위치 추출 | 시간대별 조도·눈부심·차광 상태 |
| 콘센트 | 전기도·사진에 명시된 기호 추출 | 좌석별 접근성·포트 수·작동 상태 |
| 책상 | 보이는 평면 형태·칸막이 추출 | 높이·폭·깊이 치수, 실제 좌석 방향 |
| 경치 | 창문과 바깥 방향의 기초 정보 정리 | 앉은 높이의 시야 사진·평가. 창가라는 이유로 좋은 경치라고 단정할 수 없음 |
| 소음·통행 | 출입구·통로 근접도의 간접 정보 정리 | 시간대별 실측·사용자 평가. 근접도와 실제 소음을 구분 |

**AI가 도면에 없는 시설을 추측한 값은 관측 사실로 저장하지 않는다.** 미확인(`null`)과 부재 확인(`false`)을 구분한다. ‘전체 시설 구축 완료’를 주장하려면 실제 설비 목록이나 전수 현장 점검 결과를 대조 기준으로 확보해야 한다.

## 9. 최종 스키마와 서비스 연결

`target_schema.json` v1.1에 최종 번들의 구조를 명시했다. v1.0에서 부족했던 libraries·rooms·room_features와 도면 경로·유형·벽 표현을 보완했다. 기존 후보 CSV/JSON은 최종 번들이 아니므로 자동 변환 완료로 간주하지 않는다. 현재 CSV는 최종 번들로 이관하기 전 단계의 정적 추출·조사 산출물이다.

- `library` / `room`: 기관 위경도·열람실·정원·이용규정·구조화된 운영시간.
- `room_feature`: 열람실 특성과 전 좌석 적용 여부.
- `source`: 원본 URL·해시·날짜·사용 조건.
- `map`: 도서관·층·방(library/floor/room), 가로·세로, 좌표 단위, 원본 source.
- `seat`: 내부 ID, 공식 ID·표시번호, 방, `map_id`, 경계 상자(bbox)·방향, 검수 상태.
- `facility`: 유형, 점·면·접근점, `map_id`, 원본 source, 검수 상태.
- `map_transform`: 프레임 사이의 변환과 실제 기준점.
- `walkway_node/edge`: 출입구·복도 연결, 거리와 단위.
- `seat_feature`: 좌석별 특성값·단위·관측 조건·근거·검수 상태.

웹에서는 같은 `map_id`의 배경과 좌석·시설을 SVG `viewBox`로 겹쳐 그린다. 정규화 위치를 계산할 때는 해당 지도 프레임의 크기를 사용한다. 사진의 원근과 지도 스케일을 검증하지 못했다면 실거리나 시설 근접도를 활용하는 추천은 보류한다.

추천은 필수 조건 필터 → 취향별 만족도 점수 → 선택·만족도에 따른 개인화 순서로 시작한다. 정적 특성 CSV와 행동 로그는 분리한다. 행동 DB에는 `recommendation_id`, `user_id`, 노출 후보와 순서, 당시 조건, 선택, 이용 확인, 평가, 이벤트 시각, 추천 버전을 기록한다. 클릭과 실제 착석을 동일하게 취급하지 않으며, 미선택을 즉시 ‘싫어요’로 학습하지 않는다. 공개 예약 파일에는 이러한 개인화 학습에 필요한 연결 키가 없다.

## 10. 완료 판정과 착수 순서

검수 완료 조건:

- [ ] 원본의 현재성과 이용 허용 범위를 확인한다.
- [ ] 현재 공식 목록과 모든 좌석의 ID·표시번호가 1:1로 대응하는지 확인한다. 중복·누락·폐기 좌석을 처리한다.
- [ ] 지도 범위·중첩·원점·스케일·오프셋을 검증한다. 원본 좌표와 정규화 좌표를 대조한다.
- [ ] 시설 유형별 근거와 위치를 확인한다. 부재 확인과 미확인을 구분한다.
- [ ] 층·방·시설의 프레임 정합과 문·복도 연결을 확인한다.
- [ ] 픽셀과 실거리의 단위를 검증한다.
- [ ] 웹에서 선택한 좌석이 실제 번호·위치와 맞는지 확인한다.
- [ ] CSV의 BOM·키 순서·날짜·결측치와 JSON과의 일치 여부를 점검한다.
- [ ] 현황·성별·개인 이용 시각이 정적 데이터에 섞이지 않았는지 확인한다.

착수 우선순위:

1. **성남중앙 A구역의 169개 좌석을 전수 검수**하여 ‘사진 → 수치 → 웹 좌석도’ 흐름을 완료한다.
2. **동백 또는 죽전 한 관에서 번호 매핑과 층별 화장실 정합까지 완료**한다. 에어컨·콘센트는 해당 관의 설비도 또는 현장 조사로 보완한다.
3. 좌표를 확보한 나머지 용인 도서관으로 같은 방식을 확장한다. 기흥의 누락 좌석 16개를 확인한다.
4. 성남의 다른 12관은 허용된 원본을 확보한 뒤 진행한다. 현재 CSV의 정원만으로 번호·위치를 합성하지 않는다.
5. 모든 기관의 일괄 완료를 약속하지 말고, 좌석 ID·좌표·시설 종류·검수·현재성을 기준으로 관별 완성률을 따로 집계한다.

## 11. 사용자가 추가 지정한 참고 저장소

[Dev-zeno/opendata_plr 검토서](OPENDATA_PLR.md)에 커밋·실제 필드·응답 처리·예시 데이터와 현황 미상 처리 문제를 정리했다. 이 검토는 위 27관 조사 뒤 추가한 확장 근거다.

- [기관 후보 91행](../catalog/reference_library_candidates.csv), [열람실 링크 후보 222행](../catalog/reference_room_candidates.csv)을 새로 정리했다. 기존 27관과의 기관 ID 대응은 아직 완료하지 않아 단순 합산하지 않는다.
- 링크가 있는 열람실은 205개지만 직접 이미지 URL은 0개다. 링크 원본은 접속하지 않았으므로 현재 좌석표나 좌표를 확보한 것으로 판정하지 않는다.
- 후보 기관은 지역코드+도서관ID, 후보 열람실은 그 키+열람실ID를 사용한다. 이름이 같은 중앙도서관들을 합치지 않는다.
- 실제 좌표와 시설을 확인한 후보만 타당성 판정표로 승격한다. API 미수신을 전석 공석으로 바꾸거나 MOCK_LIBRARIES를 데이터로 가져오지 않는다.
