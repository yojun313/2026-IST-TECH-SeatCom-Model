# 작업: v1 좌석 추천 모델 테스트 (유저 테스트 데이터셋 + 정답 로직 변화 + 일반 평가 기준)

## 배경과 범위
- 테스트 대상은 **v1 데이터(synth-1.0, 세션 163,767건)로 학습된 `seat_model/models/v1-20261115/`**이다.
- 목표: 학습에 쓰지 않은 **새 가상 사용자**로 모델이 얼마나 맞는지 본다. 이때 두 가지를 함께 본다.
  1. 우리 가정이 맞는 세계(base)에서의 성능
  2. 정답 로직이 우리 가정과 달라질수록(혼합 강도 λ) 성능이 얼마나 버티는지
- v2 데이터·모델은 없으므로 다루지 않는다(맨 아래 "제외 범위").
- 경로 규칙
  - 코드: `seat_model/model_test/` (사용법은 같은 폴더 `README.md`)
  - 설정: `seat_model/config/model_test.yaml` — 시드, 정답 로직 파라미터, 테스트셋, **통과 기준**을 모두 여기서만 관리한다
  - 산출물: `seat_model/exports/test_v1/`(git 제외), `seat_model/reports/`
  - 테스트 DB: MongoDB **`user_test`** (운영 DB `library`와 분리)
- **절대 바꾸지 않는 것**: 운영 DB `library`(배포 사이트가 읽음), `data/libraries/synthetic/*.jsonl`, `seat_model/models/v1-20261115/`, `seat_model/exports/train_v1/`, 커밋되지 않은 생성기 수정분
- 참고: 운영 DB `library`와 `data/libraries/synthetic`은 이미 synth-1.1 데이터에 칸막이 수정(1인 칸막이 책상만 칸막이 1)까지 들어가 있어 **학습 데이터가 아니다.** 학습 기준은 `seat_model/exports/train_v1/`이다.

## 0.5단계: 선행 버그 수정 — 완료(승인됨)
- **필수 조건 하드 필터 미적용**: 예전 `inference.py`의 `final = s + 1000·req_ok` 때문에, 조건을 만족하는 좌석이 k개보다 적으면 금지 좌석이 추천에 섞였다.
- 수정(`seat_model/train/inference.py` `recommend`)
  - 점수는 학습 때와 같이 **빈자리 전체로 계산**하고, 조건 밖 좌석은 **결과에서 뺀다.** 점수 계산 전에 빼면 `ctx_n_avail`·빈자리 평균 중심화 특징이 학습 분포와 달라지기 때문이다(`ctx_req_ok`도 모델 특징이다).
  - 남은 좌석이 k개 미만이면 그 수만큼만 반환하고, 0개면 빈 목록 + `reason: "no_eligible_seat"`를 반환한다. 결과에 `excluded_by_requirements`(뺀 좌석 수)를 넣는다. 동점은 seat_id 오름차순(안정 정렬)이다.
  - 회귀 테스트: `seat_model/tests/test_requirements_filter.py`(DB 없이 작은 스냅숏으로 3건). 기존 `test_inference.py`의 "항상 5개" 기대는 새 규칙(조건 만족 좌석 수까지)으로 고쳤다. 모델 파일은 바꾸지 않았다.
- **백엔드 영향**: 백엔드는 조건 밖 좌석도 경고(`필수 조건 밖 좌석`)와 함께 보여주던 방식이었는데, 이제 그런 좌석은 결과에 오지 않는다. 배포 사이트는 백엔드를 재시작하면 반영된다.
- 오프라인 트랙 채점은 학습 때(`run.py`)와 같은 규칙(조건 만족 좌석을 먼저 놓기)을 그대로 쓴다. 학습 지표와 비교 가능하게 하기 위해서다.

## 2단계: 정답 로직과 테스트셋 — 완료
모든 세트는 **같은 사용자·같은 요청 맥락(시각·열람실·점유·노출)**을 공유하고, **선택과 정답만 다르다.** 그래서 세트 간 비교가 짝지어진다.

**정답 효용**: `U_truth(λ) = (1 − λ)·U_base + λ·U_new`
- `U_base`: synth-1.0 생성기의 참 효용 `Σ w·(1 − |t − x|) − 0.5·소음회피·소음`(고정 생성기와 오차 0으로 확인)
- `U_new`: 아래 효용 모듈의 합

| 모듈 | 내용 | 종류 |
|---|---|---|
| A1 형태 변경 | 선형 거리 → 가우시안 이상점 `w·exp(−(x−t)²/2σ²)`, σ는 사용자·특징별 0.15~0.35 | 효용 |
| A2 탈락 조건 | 콘센트 필수인데 콘센트 없음, 추위 타는데 에어컨 2m 이내, 소음 회피 큰데 소음 지수 0.45 초과 → −1.0 | 효용 |
| A4 상호작용 | 좌석 온도 × 선호 온도, 저녁 × 밝기, 혼잡 × 소음, 노트북 × 넓은 책상 | 효용 |
| C1 숨은 취향 | 관측 프로필에 없는 칸막이·출입구·책상 높이 선호, 긴 공용 테이블 기피 | 효용 |
| B1 고려집합 | 노출 좌석 + 출입구에서 가까운 N석(8~30)만 둘러본다 | 선택 과정(요청마다 확률 λ) |
| B3 습관 | 직전 좌석이 비어 있으면 다시 앉고(확률 0.1~0.5), 아니면 같은 책상 묶음 우선 | 선택 과정(요청마다 확률 λ) |
| R 추천 신뢰도 | 추천 신뢰도 `rec_trust × (1 − λ·0.75)`. λ = 1이면 원래의 25% | 선택 과정 |

- 노트북 사용자 × 노트북 금지 좌석은 모든 세트에서 선택 불가(−inf)로 synth-1.0과 같다.
- 파라미터는 모두 `model_test.yaml`의 `truth`에 있다. **테스트 결과를 보고 바꾸지 않는다.**
- R 배율 0.25는 모델 결과 없이 데이터만으로 정했다. 사용자 600명 표본에서 배율 1.0 / 0.75 / 0.5 / 0.25 / 0을 비교해, 라벨 반응도 증가가 거의 멈추는 지점(0.25와 0의 차이 0.004)을 골랐다.

**테스트셋** (도메인 우선순위 A2 → A4 → B1+B3 → C1 순으로 누적)

| 세트 | λ | 모듈 | 신뢰도 배율 | 정답 상관 ρ | 1위 좌석 일치 | 라벨 반응도 |
|---|---|---|---|---|---|---|
| `base` | 0 | – | 1.00 | 1.000 | 1.000 | 0 |
| `base_resim` | 0 | – (선택 난수만 다름) | 1.00 | 1.000 | 1.000 | 0 |
| `base_lowtrust` | 0 | R | 0.25 | 1.000 | 1.000 | 0 |
| `form` | 1 | A1, R | 0.25 | 0.908 | 0.675 | +0.020 |
| `c_a2` | 1 | +A2 | 0.25 | 0.873 | 0.662 | +0.035 |
| `c_a4` | 1 | +A4 | 0.25 | 0.871 | 0.643 | +0.035 |
| `c_b` | 1 | +B1, B3 | 0.25 | 0.871 | 0.643 | +0.031 |
| `real_0.25` | 0.25 | 전부(+C1) | 0.81 | 0.967 | 0.841 | +0.004 |
| `real_0.50` | 0.50 | 전부 | 0.62 | 0.924 | 0.737 | +0.012 |
| `real_0.75` | 0.75 | 전부 | 0.44 | 0.880 | 0.655 | +0.027 |
| `real_1.00` | 1 | 전부 | 0.25 | 0.838 | 0.591 | +0.041 |

- **정답 상관 ρ**: 세트 정답과 base 정답의 요청별 순위상관 평균
- **1위 좌석 일치**: 세트 정답 1위와 base 정답 1위가 같은 요청 비율
- **라벨 반응도**: 실제 선택이 세트 정답 1위를 따르는 비율 − base 정답 1위를 따르는 비율. 클수록 선택 라벨이 정답 변화를 반영한다
- **대조군 두 개**
  - `base_resim`: 선택 무작위성의 바닥값. 정답이 같아도 선택의 70%가 base와 달라진다.
  - `base_lowtrust`: R의 효과만 분리한다. 정답 로직 효과는 `base_lowtrust` 대비로 읽는다.

## 3단계: 평가 방식
| 트랙 | 대상 모델 | 경로 | 쓰는 곳 |
|---|---|---|---|
| **오프라인** | 7개: `clogit_b_no_exp`(서비스), `clogit_a_full`, `lgbm_b_no_exp`, `service_rule`, `entrance_nearest`, `popularity`, `random` | `user_test` → `data.py` → Parquet → `run.py`와 같은 평가 | 정확도·일반화·사용자 유형·정답 변화 강건성 |
| **서비스** | `SeatRecommender`(clogit 서비스 모델 + 사용자별 온라인 갱신) | `inference.py` 직접 호출 | 순차 모드 성능, 일관성, 견고성, 지연 시간 |

- `xgb`는 저장된 모델 파일이 없어(결과 Parquet만 있음) 재학습 없이는 평가할 수 없으므로 제외한다. 신경망은 학습되지 않았다.
- `popularity`는 학습 산출물(`train_v1`)의 학습 분할 좌석 선택률을 쓴다.

**오프라인 트랙 주의사항**
- `data.py`의 `build()`는 사용자 분할(70/15/15)과 홀드아웃 열람실을 무작위로 새로 만든다. 테스트에서는 이렇게 덮어쓴다(`train/data.py`는 수정하지 않고 테스트 코드에서 감싼다).
  - 테스트 사용자는 전원 `test`
  - 홀드아웃 열람실은 `exports/train_v1/splits.json`의 4개 그대로
- 이력 특징은 테스트 사용자 자신의 과거 요청만으로 계산된다(`data.py` 기본 동작).
- 세트마다 `load_user_test.py --set <세트>` → `data.py` → 평가를 반복한다. 특징 중 선택에 의존하는 것(이력·취향 추정)만 세트마다 달라진다.

**서비스 트랙의 온라인 상태 처리**
- `observe()`는 상태를 바꾸고 `save_state()`는 모델 폴더의 `online_state.json`을 덮어쓴다. 테스트에서는 상태를 메모리 복사본으로만 쓰고 `save_state`를 막는다. 테스트 후 모델 폴더 파일 해시가 그대로인지 확인한다.
- 두 모드를 나눈다.
  - **콜드 모드**: 요청마다 빈 상태에서 시작
  - **순차(prequential) 모드**: 사용자별로 시간순으로 추천 → `observe` → 다음 요청

## 4단계: 평가 지표와 구간
**지표**

| 구분 | 지표 | 역할 |
|---|---|---|
| truth 기준(세트별 `u_true`) | NDCG@5, Oracle HitRate@1, 상위 1개 좌석의 참 효용 백분위 | **주 지표** |
| `y_chosen` 기준 | HitRate@1/3, MRR | 보조 지표 |

- 신뢰구간: **사용자 단위 부트스트랩** 95%, 1,000회(`train.yaml`과 같은 단위)
- truth를 주 지표로 두는 이유
  - 생성기의 노출 목록이 `service_rule`과 같은 식이라, `y_chosen` 지표는 `service_rule`에 유리하다.
  - 선택이 확률적이라 세트 간 `y_chosen` 차이가 작다(라벨 반응도 최대 +0.041).

**구간** (스윕 손잡이를 따로 만들지 않고, 일반 데이터 안의 자연스러운 차이로 나눈다)
- 신규 / 이력 있음(`hist_n` 0 / 1 이상)
- 관측 정보량(unknown 0–2 / 3–4 / 5+)
- 열람실(학습 / 홀드아웃 4개)
- 혼잡도(하 / 중 / 상, 3분위)
- archetype 6종

구간마다 요청 200건 이상, 사용자 30명 이상일 때만 판정한다.

## 5단계: 일관성·견고성 (서비스 트랙, pytest)
특징값이나 좌석을 인위적으로 바꾸는 검사는 실제 데이터와 맞지 않으므로 하지 않는다.

| 코드 | 검사 | 방법 |
|---|---|---|
| M1 결정성 | 같은 상태 복사본으로 같은 입력 2회 → 같은 출력 | 일반 데이터에서 요청 1,000건 |
| M4 방향성 | clogit: `match_*` 계수 부호가 0 이상인지(계수 검사만). `laptopAllowed`는 열람실 단위 규정이라 계수가 0이므로 제외. `inf_x_*` 음수 계수(현재 brightness −0.006, deskHeight −0.023)는 경고로 보고 | 모델 파일 |
| | LightGBM: 실제 테스트 행에서 `match_k` 값과 그 특징 기여도(`predict(pred_contrib=True)`)의 순위상관이 0보다 큰지 | 일반 데이터, 값 변경 없음 |
| M9 필수 조건 | 노트북 필수 사용자 출력에 노트북 금지 좌석 0건 | 일반 데이터 전체 |

- 방향 반전(이전 M6)은 clogit에서 `match_*` 계수가 양수이면 자동으로 성립하므로 M4에 합쳤다.
- 이전 M2·M3·M5·M7·M8과 코너 케이스·골든 케이스는 뺐다. 인위적 조작이 필요하거나 일반 기준과 겹치기 때문이다.

**견고성(R1~R8)**: 통과/실패가 아니라 실제 동작을 기록하고, 기대와 다르면 버그 목록(`seat_model/reports/model_test_bugs.md`)에 올린다. 코드는 고치지 않는다(0.5단계 제외).

## 6단계: 통과 기준 (`model_test.yaml`의 `criteria`)
| 영역 | 대상 세트 | 기준 |
|---|---|---|
| 1. 정확도 | `base` | 서비스 모델의 NDCG@5와 Oracle@1이 `service_rule`·`popularity`보다 높고, 사용자 단위 신뢰구간이 겹치지 않음. HitRate@3은 보조(같은 비교를 보고) |
| 2. 일반화 | `base` | 모든 구간에서 NDCG@5가 `service_rule` 이상이고, 전체 대비 하락이 10%p 이하 |
| 3. 사용자 유형 | `base` | 가장 낮은 archetype도 NDCG@5가 같은 archetype의 `service_rule` 이상 |
| 4. 정답 변화 강건성 | `real_0.25`~`real_1.00`, 누적 세트 | 모든 세트에서 NDCG@5가 `service_rule` 이상. 역전되면 그 λ·모듈을 보고. λ에 따른 하락 기울기와 누적 세트별 기여를 보고 |
| 5. 규칙·안정성 | 전체 | 필수 조건 위반 0건(0.5단계 수정 후), 정상 데이터에서 예외 0건, R1~R8 동작 기록 |
| 6. 일관성 | – | M1 100%, M4 위반 0(음수 `inf_x`는 경고) |
| 7. 서비스 요건 | `base` | 요청당 p95 지연 ≤ 50ms(빈자리 176개 이하) |

기준에 못 미쳐도 끝까지 실행하고 원인 분석을 남긴다. **테스트 결과로 모델을 다시 학습하거나 튜닝하지 않는다.**

## 한계
- 모든 데이터와 정답은 합성이다. 정답 로직(A1~C1, B, R)도 우리가 정한 가정이라, 어느 로직이 실제와 가까운지는 이 테스트로 알 수 없다. 사람 라벨(D2)은 진행하지 않기로 했다.
- 선택이 확률적(rationality 중앙값 4.9)이라 라벨 반응도가 크지 않다(최대 +0.041). 참고로 사용자 300명 표본에서 선택 정확도를 2배·4배로 올리면 `real_1.00`의 반응도가 각각 약 +0.08·+0.12로 커졌다. 이번 데이터셋에는 적용하지 않았다.
- 배포 환경(synth-1.1 + 칸막이 수정)과 설문 형식 입력으로 만든 서비스 조건 테스트셋(T2)은 아직 없다. 이번 결과는 모델이 학습한 환경 기준이다.
