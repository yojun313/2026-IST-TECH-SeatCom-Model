# 열람실 좌석 추천 서비스용 데이터 모음

조사일: 2026-11-14

**핵심 데이터 6종 + 위치·운영·일정 보조 데이터 3종**을 추렸습니다. 핵심 중 파일데이터 5종의 원본을 실제 다운로드했고, ZIP 내부를 포함한 CSV 6개를 UTF-8로 변환했습니다. API는 공식 문서까지 확인했으며 인증키를 사용한 실제 데이터 호출은 수행하지 않았습니다.

## 먼저 알아야 할 결론

- **열람실 추천**: 실시간 잔여좌석, 위치, 운영시간을 이용하는 구성이 가능합니다. 대상 도서관의 API 참여와 응답 최신성은 먼저 확인해야 합니다.
- **개별 좌석 추천**: 용인시 좌석 ID 목록은 확보했습니다. 그러나 현재 빈 좌석번호와 창가·콘센트·소음 등 환경 속성은 이번 데이터에서 확보하지 못했습니다.
- **예약 이력 학습**: 과거 예약 시간·취소 패턴은 분석할 수 있지만, 공개 이력에 좌석 ID와 이용자 ID가 없어 좌석별 선호·개인화 학습으로 바로 연결할 수 없습니다.
- 포털의 서비스 설명보다 **실제 원본 CSV 헤더를 우선**했습니다. 성남시 자료는 설명에 실시간 현황이 언급돼도 실제 CSV에는 잔여좌석이 없습니다.

## 3. 핵심 데이터별 해석과 한계

### 1. 행정안전부 한국지역정보개발원_(전국 통합데이터) 공공도서관 열람실 현황 실시간 정보

개별 좌석번호별 빈자리나 착석센서 관측을 보장하지 않음. 참여범위·응답 기준시각 확인.

### 2. 경기도 용인시_도서관 열람실 그룹 및 좌석 예약 정보

예약 이력은 동백·흥덕 2개관. 이력에 좌석ID·열람실ID·회원ID 없음. 만료시각은 실제 퇴실 관측 아님.

### 실시간 API의 3개 기능

한 API 상품 안의 세부 기능입니다. 별도의 독립 데이터셋 3개로 세지 않았습니다.

| 기능 | 공식 문서에 안내된 정보 | 추천에서의 역할 |
|---|---|---|
| 공공도서관 통합정보 | 위치·연락처·운영시간·휴관 | 거리·운영 여부 필터 |
| 공공도서관 운영현황 | 운영상태·방문자수·사용좌석수·좌석사용률 | 도서관 단위 현재 혼잡 정보 |
| 열람실 실시간 정보 | 열람실명·층·총좌석·사용좌석·예약좌석·잔여좌석 | 열람실 단위 빈자리 추천 |

공식 API 기본 경로: `https://apis.data.go.kr/B551982/plr_v2`

공공데이터포털에서 활용신청 후 인증키가 필요합니다. “실시간”이라는 갱신주기만으로 모든 도서관이 포함되거나 데이터 지연이 없다고 판단하면 안 됩니다. 현재 대상 지역·도서관 및 응답 기준시각을 확인해야 합니다.

## 5. 데이터 결합 시 피해야 할 오해

1. 용인시 예약 CSV에는 좌석 ID·열람실 ID가 없습니다. 좌석 목록의 2,240개 좌석에 과거 예약을 임의 배정하면 안 됩니다.
2. 예약만료일시를 실제 퇴실시각으로, 예약취소를 곧바로 노쇼로 취급하면 안 됩니다.
3. 군산의 강제종료처리횟수는 일별 운영 집계입니다. 개인별 부정이용이나 노쇼 여부를 판단할 수 없습니다.
4. 성남의 좌석현황 URL은 웹페이지 링크입니다. 공개 CSV 자체가 실시간 좌석 API는 아닙니다.
5. 전국 API의 도서관 ID와 용인 좌석목록의 열람실 ID가 같은 체계라는 근거는 없습니다. 먼저 명칭·주소·공식 ID 대응을 확인해야 합니다.

- 현재 상태: 전국 열람실 API의 잔여좌석·운영현황.
- 기본 필터: 도서관 위치·운영시간·휴관일.
- 이용조건: 해당 도서관에서 확인한 배정시간·연장·연령 규칙.
- 개별 좌석 화면까지 만들 경우: 대상 열람실 1곳을 정해 실제 도면과 좌석 환경 속성을 별도 구축. 실시간 개별좌석 상태 연동 전에는 이를 명확히 표시.

### 별도 수집할 좌석 속성의 제안 스키마

다음은 확보한 공공데이터가 아니라 추가 수집용 설계 제안입니다.

```text
library_id, room_id, seat_id, seat_label
x, y, near_window, has_outlet, has_partition
laptop_allowed, accessible_seat, distance_to_entrance
attribute_source, attribute_checked_at
availability, availability_source, availability_observed_at
```

미확인 속성은 `false`나 0으로 채우지 말고 미확인 값으로 보존하세요. 배치도·환경 속성과 실시간 상태는 각각 출처·확인시각을 기록하면 추천 근거를 설명하기 쉽습니다.
